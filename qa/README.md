# IPTV 手机与 TV 全量回归

使用手机真机和 TV 真机或模拟器。从项目根目录运行，准备 ADB、Python 3.10+、Pillow、FFmpeg 和 Android SDK Build Tools。手机用点按、滑动和输入框，TV 用遥控。所有业务数据通过 App UI 建立。ADB 用于安装旧版、模拟输入、读取状态及建立测试网络。新版从 App 内检查、下载和安装。

## 执行约定

- 每轮重新确认手机和原 TV 的序列号、实际安装版本和当前界面；不沿用上一轮的完成结论，不操作其他模拟器。
- 手机与 TV 同时推进，每台同一时刻只允许一个 UI 操作脚本。每一步完成后按设备报告实际结果；失败先记录界面、操作与原因，不把脚本退出当作 App 缺陷，也不跳过失败项宣布通过。
- 业务操作只通过 App 的点按、滑动、输入和遥控按键。ADB 只用于旧版卸载/安装、模拟输入、只读核验及测试转发，禁止直接写数据库、偏好、缓存或跳转业务页面。
- 普通授权、风险复选框、安装确认由测试执行者通过界面完成；只有实际无法远程处理的密码、生物识别等环节才等用户。下载慢时观察 App 状态，不能因脚本等待结束判断安装包损坏。
- 本轮产生的旧源码目录、APK、截图、视频、日志、设备临时文件、服务 PID 和端口都记入本轮清单，供最后按准确路径清理。不要把 APK 复制到设备下载目录备用，也不要复用上轮残留包。
- 不为测试改动 App 操作、焦点行为或发布脚本；系统设置确需改变时先记录原值。手机全局代理不改；TV 输入法和已授予的安装权限按用户要求保留。

## 1. 用 ADB 卸载两台设备上的 IPTV

分别在手机和原 TV 模拟器执行 `adb -s <序列号> uninstall cn.hdfk7.android.iptv`，再用 `adb -s <序列号> shell pm list packages cn.hdfk7.android.iptv` 确认目标包已不存在。每一步完成后先报告实际结果，再进入下一步。

## 2. 用发布脚本打旧包

选一个 versionCode 低于待测新版、支持应用内更新的正式旧版。使用旧版本代码；需要导出时用 `git archive` 放入本轮临时源码目录，不建立 Git 工作树。在该版本的代码目录运行仓库原有的 `upload-release.bat`，生成正式签名 APK。执行默认的清理构建和真实上传流程，不跳过上传、不另设隔离发布目录。记录本轮 APK 路径、版本、SHA-256 和签名摘要，核对公开 latest.json 及下载文件与本轮产物一致。

## 3. 用 ADB 安装旧包

分别执行 `adb -s <序列号> install <刚打出的旧版APK>`，核对两台的安装结果、版本及 APK 哈希。

旧版安装和应用内升级时，能通过模拟点按或遥控按键操作的系统授权开关及安装确认，由执行测试的人直接完成。只有遇到远程确实无法完成的验证，例如要求输入设备密码或在设备上做生物识别，才停在当前页面，说明卡在哪一步并等待用户处理。

## 4. 在旧版 App 内准备两台基线

在系统临时目录创建独立的 `iptv-qa-<唯一编号>` 子目录，设置 `IPTV_QA_OUTPUT` 指向该目录，在其中新建空文件 `.iptv-qa-run`。设 `PYTHONDONTWRITEBYTECODE=1`。旧版和新版 APK 放在临时目录外。

将自制的动态测试视频放在本轮目录，并用 FFmpeg 生成同名 TS 分片。启动 `python -B qa/fixture_server.py --media <临时目录中的MP4>`。用空闲端口建立两端的测试转发，默认 `adb -s <序列号> reverse tcp:18764 tcp:18764` 和 `adb -s <序列号> reverse tcp:18766 tcp:18766`。前者用于测试源，后者用于 HTTP 代理。端口调整时同步传给各脚本。

从桌面打开 IPTV，核对默认订阅、空收藏及 App HTTP 代理关闭。首次启动自动播放可能产生一条新的最近观看。

```powershell
$upgrade = @('--phone', $phone, '--tv', $tv, '--old-apk', $oldApk, '--build-tools', $buildTools)
python -B qa/local_upgrade.py --phase baseline @upgrade
```

脚本先验证两端旧版的版本和 APK 哈希，再并行在两台 App 里添加、启用测试源、播放、收藏，采集订阅、收藏和最近观看。两端都准备好后才生成配对基线。准备阶段中途失败时，先确认两台都运行旧版，再通过系统界面清除本次未完成的测试数据并重跑基线。配对基线完成后，升级及升级后数据核对期间保留本轮测试数据。

## 5. 用发布脚本打新版，再从旧版 App 发起升级

两台的旧版基线都通过后，在当前代码目录运行仓库的 `upload-release.bat`，执行默认清理构建和真实上传，生成并分发新版正式签名 APK。即使以前上传过也要执行本轮发布流程。核对公开更新清单以及服务器下载 APK 的版本、签名、SHA-256 与本轮产物一致，再开始应用内升级。

```powershell
python -B qa/local_upgrade.py --phase upgrade @upgrade --new-apk $newApk
```

脚本同时在两台旧版 App 检查更新、下载，每台完成后立即报告并单独保存检查点。下载等待默认 900 秒，可用 `--download-timeout` 按实际网速调整；它不修改 App 网络超时。出现「去授权」时，通过设备界面开启 IPTV 的安装权限，返回 App 点击「安装更新」，在系统安装器确认。只有符合第 3 节的等待条件时才请用户处理，处理完用相同参数继续。升级脚本核验配对基线、安装版本与 APK 哈希，再对比原订阅、收藏和最近观看。两端通过后开始新版回归。

## 6. 新版功能和界面回归

使用同一候选 APK 跑完回归。设置 `IPTV_QA_APK` 为已核验的本轮实际分发 APK 路径。若与本地发布产物哈希不一致，先查清下载、上传或缓存问题，不换一个文件路径掩盖不一致。通过正常界面、物理旋转或下文的 ADB 方法切换手机方向。TV 导航用 App 选好含多频道和分组的源。下面列出各设备命令；手机和 TV 各自按顺序执行，两台并行，不在同一设备叠加脚本：

```powershell
python -B qa/release_ui.py --device phone --serial $phone --orientation portrait
python -B qa/release_ui.py --device phone --serial $phone --orientation landscape
python -B qa/release_ui.py --device tv --serial $tv
python -B qa/tv_navigation.py --serial $tv
python -B qa/tv_exit.py --serial $tv
python -B qa/controlled_ui.py --phase hls --device tv --serial $tv
```

| 场景 | 验收 |
| --- | --- |
| 界面 | 播放页、底栏、频道分组、更多、节目单、设置、更新、源管理和收藏。核对对齐、长名称、滚动、键盘遮挡与横屏按钮可达。 |
| TV 焦点 | 首次焦点、移动、高亮、确认与返回。节目单关闭后恢复原频道。分组下键定位当前频道或首项。关闭表单键盘后仍可用方向键。 |
| 播放与设置 | 首帧、暂停和恢复、换台、重连、切线、音量、启动频道和铺满。TV 先关闭浮层，首次返回提示，2 秒内再次返回退出。 |
| 数据功能 | 新增、编辑、取消及确认删除订阅，收藏、取消收藏和最近观看。 |
| 线路与缓存 | 验证首线 404、HLS 分片挂起和备用线路出画。用 `/control?mode=release-offline` 模拟列表和 XMLTV 503，经 App 刷新、重开核对缓存，随后切回 `/control?mode=ok`。编辑 URL 后核对缓存归属。 |
| 更新与键盘 | 核对当前版本、版本说明、下载进度、取消和重试、安装授权、返回后的下载包恢复、安装成功/取消/失败。下载期间点弹窗外部不关闭或取消；取消按钮和返回键保持原行为。安全键盘通过系统状态或真机实际输入确认，不能凭截图缺失判失败。 |

两端并行运行 `controlled_ui.py --phase proxy-guide --device phone|tv --serial <序列号>`。检查代理及源站请求，核对跨入当天的节目从 00:00 显示、跨到次日的节目保留，以及当前和下一节目。手机从最近任务划掉 IPTV，TV 经系统应用详情停止 IPTV，再从桌面打开。运行 `controlled_ui.py --phase after-restart --device phone|tv --serial <序列号> --old-pid <之前输出的PID>` 验证冷启动、代理配置保留及新请求。表格中其余项目逐条走界面。代理测试前通过 App 关闭代理；复测已有表单时替换原值，不能追加。跨午夜夹具按各设备的日期和时区生成，不修改系统时间。两个设备同时测试时不得切换共享服务器故障模式影响另一台；503 故障场景共同进入、共同恢复，其他场景保持正常模式。

### 手机横屏和自动旋转恢复

远程测试可通过 ADB 临时切换手机方向。先记录当前旋转模式和方向，并记录系统是否忽略应用的方向请求。

    adb -s $phone shell wm user-rotation
    adb -s $phone shell settings get system user_rotation
    adb -s $phone shell wm get-ignore-orientation-request

执行 `adb -s $phone shell wm user-rotation lock 1` 请求横屏。OPPO PEPM00 的系统安装器可能锁定竖屏，如果画面仍未旋转，再临时执行 `adb -s $phone shell wm set-ignore-orientation-request true`。通过窗口状态的 `mRotation` 及截图或 UI 树宽高确认实际进入横屏，再继续安装器返回等用例。

用例完成、中止或失败后都要恢复记录的值。原模式为 `free` 时执行 `adb -s $phone shell wm user-rotation free`。原模式为锁定时用 `adb -s $phone shell wm user-rotation lock <原方向>` 恢复。若改过忽略方向请求的设置，用 `adb -s $phone shell wm set-ignore-orientation-request <原布尔值>` 恢复，再读回两项设置核对。本次 PEPM00 的原设置为 `free` 和 `false`。

### 版本差异规则

版本号或版本名称任意一个不同即可下载，包含版本号更低的情况；两者相同时不提供更新。下载包仍核对应用、清单版本和签名等既有校验，能否安装交由系统处理，安装完成必须核对版本号与名称均相符。覆盖：仅编号变化、仅名称变化、两者变化、完全相同、较低编号、取消安装、系统拒绝。不能用「已安装编号大于目标」认定成功。普通全量升级仍选编号递增的旧包→新版；额外版本规则用本地单元测试及明确安排的真实版本场景验证，不伪造公开清单或改写设备数据。

### 自动化断言

控件出现后再操作；保存、收藏、换台后等目标状态，不能仅靠固定短暂停顿断言。TV 启动固定按顺序：

1. 回到桌面，选中左侧红色九宫格「应用」入口，以画面中的放大、高亮确认选中。
2. 按遥控确定，确认右侧已经出现应用列表（含「获取更多应用」和应用图标）。
3. 在应用列表中移动到 IPTV，确认 IPTV 图标高亮，再按确定。
4. 确认进入 IPTV 界面，才继续业务操作。

本轮已实际验证这条路径。桌面 UI 树的 `focused` 可能与画面高亮不一致，不能据此反复发送方向键；脚本检测到重复的焦点位置时保存截图并停止方向键输入。遇到不一致时以截图核对当前画面，选中后直接按确定，再检查列表是否打开。不得将桌面 IPTV 收藏入口或「添加到收藏夹」当作应用列表入口，不直接跳转启动。手机检查桌面分页，「更多」自动收起时重新唤出控制栏并重试。节目单读取嵌套行、合并文本和同一行的独立无障碍节点，测试夹具从同一次设备时间读取获取本地日期和 UTC 偏移。HLS 卡顿夹具必须为未结束直播列表，记录请求经过首分片、挂起分片、备用线路并确认动态画面；已带结束标记的录像不属于卡顿用例。

## 7. 汇报与清理

先核对结果，按设备整理通过、失败和待验证项。再通过系统设置的 **应用 → IPTV → 存储 → 清除数据** 恢复两端 IPTV 的刚安装状态。这会清除 IPTV 的原有和测试数据，只保留两台设备上已安装的新版 App。仅操作本轮指定设备上的 IPTV。手机系统全局代理和其他 App 保持原样。

停止本轮测试服务，并撤销本轮建立的端口转发。执行 `python -B qa/cleanup.py --phone $phone --tv $tv --new-apk $newApk`。脚本检查两台的最新包、默认订阅、空收藏及代理关闭，清理设备临时 UI 树和主机临时目录里的截图、视频、日志及检查点。核验完成后，按本轮记录的准确路径删除主机上生成的新旧 APK 和其他临时测试产物。设备公共下载目录如有本轮产生的 IPTV APK，先核对准确路径再删除；不删除其他应用文件。清理时不保留主机新旧 APK，也不保留测试截图或录像，最终只保留两台已安装的新版 App。源码、QA 文档和脚本属于项目文件，保留。最终结论在会话中汇报。

可选的换台耗时测试使用单独的性能环境和启用 `APP_DEBUG_SWITCH` 的签名 Release。用夹具服务的 `/tune.m3u` 通过 App 添加订阅并选中其中一个频道，运行 `python -B qa/release_tune.py --device phone|tv --serial <序列号> --rounds 40`。对比前后版本时复用同一设备、信号和线路历史初始状态。报告记录签名 APK 的 SHA-256、换台首帧 P50/P95、首条线路成功率、恢复耗时、首帧前失败和超时次数、首帧后失败次数，以及预览截图次数和耗时。线路排序可能在预热后将备用线路提升为首条，恢复样本按实际日志计数。
